# RSI‑CCI Profit‑Target Strategy (Skill)

## Overview
This skill implements an intraday disparity20/CCI entry strategy with fixed profit target exit for KOSPI/KOSDAQ stocks using Kiwoom 1‑minute data. It supports mock/prod environments via separate .env folders and provides a live web dashboard that shows both signal history and real‑time account information (holdings, cash, P&L). The dashboard lets the user toggle between mock and prod accounts.

- **Buy**: disparity20 ≤ 100, CCI crosses -100 upward, volume ≥ MA20.
- **Sell**: Intraday profit reaches +1.5% (fixed target) – stop‑loss can be added later.

It reports win rate, average profit, and total trades over a look‑back window (default 5 days).

*User prefers concise, actionable responses; this skill is written accordingly.*

## Prerequisites
- Hermes Agent with access to Kiwoom REST API (real or mock).
- Environment files prepared under `envs/mock/.env` and `envs/prod/.env` containing:
  - `KIWOOM_REST_API_KEY_(MOCK|PROD)`
  - `KIWOOM_REST_API_SECRET_(MOCK|PROD)`
  - `KIWOOM_ACCOUNT_NO_(MOCK|PROD)`
  - `TRADING_ENV` (set to `mock` or `prod` inside each file)

- For real‑time signal visualization: Ensure the dashboard is running (`cd /home/june/trading/dashboard && python3 app.py &`).

## Step‑by‑Step Usage

### 1. Load / Update the Skill
The skill is already saved; you can view it anytime with:
```bash
skill_view(name='rsi_cci_profit_target')
```
To re‑create or modify, run:
```bash
hermes skill_manage action='edit' name='rsi_cci_profit_target' content='<SKILL_CONTENT>'
```
(Replace `<SKILL_CONTENT>` with the full SKILL.md text above.)

### 2. Prepare Environment Files
Copy the example below into `envs/mock/.env` and `envs/prod/.env`, then replace the placeholder values with your actual keys issued by Kiwoom.

**envs/mock/.env**
```dotenv
TRADING_ENV=mock
KIWOOM_REST_API_KEY_MOCK=your_mock_api_key
KIWOOM_REST_API_SECRET_MOCK=your_mock_api_secret
KIWOOM_ACCOUNT_NO_MOCK=your_mock_account_no   # 8‑digit mock account (starts with 8)
```

**envs/prod/.env**
```dotenv
TRADING_ENV=prod
KIWOOM_REST_API_KEY=your_prod_api_key
KIWOOM_REST_API_SECRET=your_prod_api_secret
KIWOOM_ACCOUNT_NO=your_prod_account_no       # 8‑digit real account (starts with 3)
```

### 3. Run a Dry‑Run Backtest (Mock or Prod)
From the trading workspace:
```bash
cd /home/june/trading
python3 scripts/run_strategy.py --env mock --stock 042660 --lookback 5 --profit-target 1.5
```
Replace `--env mock` with `--env prod` to test against the real server (still dry‑run unless `--execute` is added).

Optional arguments:
- `--stock`: Kiwoom 6‑digit code (default: `042660`).
- `--lookback`: number of lookback days for warm‑up (default: 5).
- `--profit-target`: target profit percent for exit (default: 1.5).
- `--execute`: if set, places real orders (use with caution).
- `--quantity`: order quantity in shares (default: 1).

### 4. Run with Order Execution (Mock First!)
To place actual orders in the mock account:
```bash
python3 scripts/run_strategy.py --env mock --stock 042660 --execute --quantity 1
```
Verify that orders appear in the mock account and that you receive a Telegram notification (if Hermes is configured for telegram).

### 5. Real‑Account Smoke Test
After confirming the mock works, repeat with `--env prod` and a very small quantity (e.g., 1 share) to ensure order routing, fee handling, and telegram alerts function correctly in the real account.

### 6. View the Live Dashboard
Start the dashboard (if not already running):
```bash
cd /home/june/trading/dashboard
python3 app.py &
```
Then open a browser to `http://<host>:5000` or, if you have set up a Caddy reverse proxy, to your custom domain (e.g., `https://june-kiwoom.duckdns.org`).  
Use the environment selector at the top‑left to switch between mock and prod accounts; the account info card will update accordingly.

### 7. Automation with Hermes Cron (Optional)
To run the strategy every minute during market hours and send alerts (or place orders if `--execute` is used):
```bash
hermes cronjob create \\
    --name rsi_cci_live \\
    --schedule '*/1 9-15 * * 1-5' \\
    --prompt \"cd /home/june/trading && python3 scripts/run_strategy.py --env prod --stock 042660 --execute --quantity 1\" \\
    --workdir /home/june/trading \\
    --deliver telegram:<your_chat_id>
```
Adjust `--deliver` to `origin` to receive messages in the Hermes WebUI, or to a specific Telegram chat.  
See `references/cron_fix_20260601.md` for lessons learned about fixing the cron job path issue.

## Notes & Pitfalls
- **Data Warm‑up**: The strategy uses 20‑period moving averages; the runner pulls the previous calendar day to warm up indicators.
- **Price Sign**: Kiwoom returns signed strings (e.g., `+126400` or `-125800`). The shared modules take the absolute value (`abs(pd.to_numeric(...))`) so comparisons work correctly.
- **Market Holidays**: Non‑trading days yield zero bars; the runner skips those dates automatically.
- **Profit Target Only**: This version does **not** implement a stop‑loss; you may add one (e.g., ‑1 % or ‑5 %) by extending the exit logic in `shared/strategy.py`.
- **Over‑fitting**: Parameters (disparity20 ≤ 100, CCI ‑100 cross, +1.5 % target) were chosen based on exploratory back‑test; re‑evaluate on out‑of‑sample periods before live deployment.
- **Account State Check**: Before running, consider querying the account via `kt00004` (see `shared/order.get_available_cash`) to confirm sufficient buying power and no conflicting positions.
- **Environment Separation**: Because mock and prod credentials are stored in separate files under `envs/`, there is no risk of accidentally using real keys in mock mode (or vice‑versa) as long as you point `--env` to the correct folder.
+ **File Permissions**: For security, set `.env` file permissions to `600` (readable/writable only by the owner) to prevent accidental exposure of API keys.
- **Dashboard Connection**: The dashboard displays signals from the most recent strategy run. To see signals from a specific environment (mock/prod), run the strategy with the corresponding `--env` flag before viewing the dashboard.
- **Cron Job Path Fix**: Earlier cron jobs failed because they tried to run `python3 monitor_profit_exit.py` from the wrong directory. The fix is to either use an absolute path or set the working directory via `--workdir` and/or wrap the call in a shell script that `cd`s to `/home/june/trading`. See `references/cron_fix_20260601.md`.
- **Time Parsing in Dashboard**: Ensure `signals.csv` timestamps are in `YYYYMMDDHHMMSS` format; the Flask app parses them with `format='%Y%m%d%H%M%S'` to avoid the “1970‑01‑01” bug.
